The boundary

GPU execution is not GPU code generation

Established

  • X_eTaL source, lowered by its own tool, runs on the physical Adreno 702 and matches the evaluator on 71 of 71 outputs.
  • Mojo code compiled for the Cortex-A53 drives the same GPU through a C ABI and matches two oracles on 24 of 24.
  • Every intermediate form is captured as text: Core, XIR, OpenCL C, SPIR-V, NIR, Adreno disassembly, LLVM IR, ARM64.
  • Nothing was installed on the board. Binaries were cross-built on Arch and copied over.

Not established

  • No Mojo-authored GPU kernel. In both paths the kernel is generated OpenCL C; Mojo orchestrates from the CPU.
  • No speedup. Eight-element programs prove execution and agreement, nothing about throughput or the crossover size.
  • No Vulkan dispatch on the Adreno yet. Turnip reports 1.0; the host demo wanted 1.1.
  • No Mojo compiler or runtime on the board. The ordinary Mojo executable path failed with SIGILL.

Each handoff document ends with a section titled "What this does not establish"

I want to keep these two columns separate in every public claim. Running a GPU from a language is one achievement. Having that language's compiler emit the GPU kernel is a different one, and for Mojo on this GPU it remains future work.
