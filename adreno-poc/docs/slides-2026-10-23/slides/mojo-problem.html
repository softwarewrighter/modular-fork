Path two: Mojo

Mojo has no Adreno target, so Mojo takes the host's seat

Three walls

  • No Qualcomm, OpenCL or Vulkan target: Mojo's runtime looks for CUDA, HIP and Metal only.
  • No compiler on the board: 1.7 GiB of RAM against a documented 8 GB, and no pip in the image.
  • A normal cross-built Mojo executable died with SIGILL: the runtime library uses LSE atomics the Cortex-A53 lacks.

Three doors

  • Cross-compile on Arch to an object: --emit object, target aarch64-unknown-linux-gnu, CPU cortex-a53.
  • Export one C-ABI function from Mojo; a 30-line C launcher provides storage, so no Mojo runtime is linked.
  • A Rust bridge with a C ABI hands the work to the same XIR, OpenCL emitter and runtime X_eTaL used.

threshold.mojo

LLVM IR, ARM64 object

C launcher + Rust bridge

OpenCL C, rusticl

Adreno 702

The executable needs only libc and the bridge library; the SIGILL diagnosis is a likely cause, not a traced fault address

This is the honest version of Mojo on this board. Mojo runs on the ARM cores and asks for GPU work through a C ABI. The GPU kernel is still generated OpenCL C. What Mojo contributes is the host program, its reference computation and the check, all compiled by Mojo for a CPU Modular never listed.
