How they were checked

Ints exactly, Floats to a relative 1e-5, every element and not a sample, against the evaluator baselines copied unchanged from X_eTaL-gpu's regression tests. The device selector refuses anything that is not the one Qualcomm GPU.

The one board-specific change

The default 256-item work-group passed the maps and failed the reductions: the compiled reduce_max_long kernel allows at most 192 work-items on this GPU. A schedule file with work_group = 128 fixed it. No emitter or runtime change.

RESULT: 5 of 5 X_eTaL source demos agree with evaluator baselines on physical FD702

The reduction failure is the interesting part. The device advertises 512 work-items, but a kernel's own register and shared-memory needs lower the limit per kernel, and OpenCL tells you only when you ask the compiled kernel. X_eTaL-gpu already had per-device schedule files for exactly this reason, so the fix was eight lines of TOML.
